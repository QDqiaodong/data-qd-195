# 多罐演练整数台账离线转换

多罐混合演练结束后，v1 模拟器给出的是精确有理数质量；教学组的物料台账只接受整数计量单位。本工具把一份完整 v1 计划中**选定的一个组分**离线转换成完整的整数台账：逐格取整不会让罐里凭空多出或少掉一个单位，已经登账的行（pin）原样对上，算不出满足口径的整批数据时明确报告冲突，绝不交付可计算的前缀。

- 只做离线精确计算，不连接实验设备、不访问外部服务；全部样例为合成数据。
- 精确轨迹完全沿用 [v1 契约](contract.md)：同一步的全部流出使用同一开步物料组成，流入在闭步才混合。整数值只写入台账，**不反过来参与物理模拟**；演练计划不是待优化的操作指令，不调换、不删减任何转移。
- 全部质量、单位数按 `Fraction` 精确计算，不以容差解释任何不等号；实现只用 Python 标准库。

```sh
python -m tank_transfer.quantize --input JOB --output DATASET
```

DATASET 原子新建，绝不覆盖已有文件或符号链接。JOB 不合法（含物理不成立的计划）或文件读写失败时退出 2，原因写 stderr，不发布新数据集——即便前面的步骤已可配平或某个 pin 已知冲突。`balanced` 与 `conflict` 都是正常业务结果，均退出 0。

## JOB

严格 UTF-8 JSON 对象，最多 2097152 字节；拒绝重复键、额外字段、缺失字段、非有限数（`NaN`/`Infinity`）与非法数值类型。顶层恰好四个字段：

| 字段 | 说明 |
| --- | --- |
| `plan` | 完整 v1 计划（`species`、`tanks`、`steps`），字段、物理规则与上限完全沿用 v1；本入口另限 **80 罐、8 组分、16 步**，允许零步 |
| `species` | 选定的一个组分 ID；只有该组分写入整数台账，但整个计划仍被校验并模拟 |
| `quantum_g` | v1 `number` 格式的正十进制字符串：台账的一个单位对应多少克 |
| `pins` | 0..2048 条已登账行 |

### `pins`

```json
{"kind": "initial", "item": "A", "units": 1}
{"kind": "closing", "item": "A", "step": "s2", "units": 0}
{"kind": "transfer", "item": "ab", "step": "s1", "units": 1}
```

- `kind` 为 `initial`、`closing`、`transfer` 之一。初始行无 `step`；闭步行与转移行必须有 `step`，指 v1 步 ID。初始及闭步的 `item` 是罐 ID，转移的 `item` 是该步内的转移 ID（转移 ID 只要求步内唯一，定位因此是 `[step, item]`）。
- `units` 是 0 至 10^18（包含）的 JSON 整数；布尔值不是整数。
- 未知行（罐、步、步内转移不存在）或重复定位（同 `kind`/`step`/`item`，即便重复值相等）都是**非法输入**，退出 2。正确定位但值不在该行的取整域内是**业务冲突**（见下），不是格式错误。pin 不能被忽略、移动或改写。

## 取整域与过账口径

对每一行（每个初始罐、每步的每笔转移、每个闭步罐，包括零值行），设其精确质量为 `m`，`x = m / quantum_g`：该行只能记为 `floor(x)` 或 `ceil(x)`；两者相同（`x` 为整数）时只能记该值。数值判断精确到有理数。

在每一步，对每罐依次过账：

1. 从该罐**整数开步余额**（第一步用初始行，否则用上一闭步行）扣去该步本罐所有**整数出流**（转移行）。这个扣完、还没合入流的余额，必须落在该罐**精确开步质量减去精确出流总质量**折算单位后的 `floor` 与 `ceil` 之间。它不另写一行，也不计入误差代价。于是完全抽空的罐在接收同一步到货前不能留有账面残余，也不能先借用同一步到货。
2. 再把记在转移行里的同一个整数值加到接收罐，得到各罐闭步行。

**守恒总额**：初始整数余额之和取精确初始总质量折算单位后的最近整数，恰在中点（`.5`）取偶数。由于每个转移行既是一次出流也是一次入流，该总额在每个闭步自动保持不变，无需另设行。

## 最优解与平局

存在满足口径与全部 pin 的解时，按以下顺序唯一选择：

1. 最小化**全部台账行的绝对误差之和**：每行的整数记账值与其精确单位数之差的绝对值，含已被 pin 固定的行；
2. 精确代价相同时，比较完整的整数向量并取**字典序最小**者，按数值比较。向量顺序为：先按罐 ID 升序排初始行；再按 plan 的步骤顺序，步内先按转移 ID 升序排转移行、再按罐 ID 升序排闭步行。ID 按原字符比较。

罐、同一步内的转移、pins 的输入排列不影响结果（平局规则只引用 ID 与计划步骤顺序）。找不到满足口径和所有 pin 的解时，交付恰好 `{"status": "conflict"}`，不交付任何前缀。

## DATASET

成功时为：

```json
{"status": "balanced", "species": "salt", "quantum_g": "1", "total_units": 1,
 "initial_units": {"A": 1, "B": 0},
 "steps": [{"step_id": "s1", "transfer_units": {"ab": 0},
            "closing_units": {"A": 1, "B": 0}}],
 "absolute_error_units": "3"}
```

- `quantum_g` 保留 JOB 中的原字符串；`total_units` 为守恒总额（JSON 整数）。
- `initial_units` 与各 `closing_units` 的键是罐 ID，`transfer_units` 的键是该步的转移 ID，值都是 JSON 整数。步骤数组包含计划的每一步（保持计划顺序），空转移步的 `transfer_units` 是空对象。
- `absolute_error_units` 是全部行绝对误差之和的精确值，用既约分数或整数的字符串表示（如 `"3"`、`"3/2"`）。

## 实现对账口径的说明（供复核）

把每行写成 `floor + delta`（`delta ∈ {0,1}`）后，过账口径等价于一个分层图上的最小费用循环：初始行、转移行、闭步行各是一条容量 1 的弧，未过账的中间余额是容量为窗口宽度（0 或 1）的零代价弧，节点供需由各行的精确下取整部分推出。弧费用取 `1 - 2*frac`（绝对误差的 delta 系数），乘以公共分母与 `2^N` 后再加上字典序位 `2^(N-1-pos)`，一次最小化先得到最小绝对误差、再得到字典序最小向量。整数容量与整数供需保证最优解为整数；分层图无环，初始势一次拓扑扫描可得，随后逐条最短增广路完成精确最小费用循环。全部计算只用 Python 标准库。

自动测试 `tests/test_quantize.py` 覆盖全部验收场景、零步中点取偶、空转移步、非单位量子、不同步同名转移、错误 selector、域外 pin、末步物理无效优先于 pin 冲突、已有输出（含符号链接）不覆盖、输入排列不变性，并用独立核对器从 v1 精确证据复核取整域与逐步过账、在小输入上对照枚举求得的精确代价与平局结果，以及在资源上限内复核密集夹具的整份规范结果。既有 v1 模拟、样本登记册、化验、工单排程与配方入口的输入、输出与异常契约不变。
